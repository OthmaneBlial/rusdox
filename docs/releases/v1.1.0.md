# RusDox v1.1.0 Release Evidence

Published on 2026-09-01 from source commit
[`b3a30b3`](https://github.com/OthmaneBlial/rusdox/commit/b3a30b3274c5c5d8ed54c0854e79e95973caa9cc),
tagged `v1.1.0`. This release adds
the verified first-run demo and tightens the public adoption, installation,
documentation, and discoverability surfaces without changing the frozen v1
document, template, renderer, or protocol contracts.

## Try it

```bash
cargo install rusdox --version 1.1.0 --locked
rusdox demo rusdox-demo
```

The demo refuses an existing destination. A successful run leaves the editable
DOCX, directly rendered PDF, page snapshot, and HTML/JSON parity reports together
under `rusdox-demo/output/`.

## Contract identity

| Surface | Release value |
|---|---:|
| Rust crate and CLI | `1.1.0` |
| Document spec | `1` |
| Word template syntax | `1` |
| Renderer API | `1` |
| Local protocol | `1` |
| MSRV | Rust `1.88.0` |

The release is additive. `rusdox demo [directory]` composes existing authoring,
rendering, and 21-check parity APIs into a safe first success; it refuses any
existing destination rather than merging into or overwriting user files.

## Adoption and discoverability changes

- `rusdox demo` is now the first README and getting-started success path.
- Release installers no longer create or modify user configuration; explicit
  config initialization remains available after install.
- GitHub Action examples pin the reviewed v1.0.0 commit and default to no write
  permission, report retention, or PR comment.
- The README names the exact dual-output/parity wedge, links real artifacts,
  presents versioned benchmark evidence, and keeps incomplete viewer and PDF
  conformance work explicit.
- Homepage documentation and six real example cards are present in HTML before
  JavaScript runs. External font requests were removed, real output is visible
  above the fold, and the obsolete sub-second claim was replaced by the
  checked-in host-separated protocol.
- The sitemap now includes the playground, signed v1 registry, performance
  budgets, and three canonical template parity reports. Duplicate legacy and
  evidence copies are `noindex,follow`, and their canonical destinations are
  shipped in the bundle.
- The AI-readable documentation corpus uses absolute public or repository URLs
  and has no unresolved relative Markdown links.

## Release intent

This release does not claim full OOXML coverage, universal Word/PDF viewer
fidelity, PDF/A, PDF/UA, tagged PDF, or complete product parity with Pandoc,
Typst, Docxtemplater, or lower-level DOCX libraries. Its claim is narrower and
testable: supported structured specs or Word templates can produce an editable
DOCX, directly rendered PDF, and inspectable parity evidence in one local
pipeline.
